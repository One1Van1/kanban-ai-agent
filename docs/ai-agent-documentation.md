# 🤖 AI Agent Documentation

## Обзор

Модуль AI Agent представляет собой интеллектуальную систему управления задачами Kanban-доски, которая автоматически анализирует, обрабатывает и перемещает задачи между колонками на основе их содержания и состояния.

## Архитектура

Модуль построен по принципу "один endpoint = одна папка" и состоит из следующих основных компонентов:

- **Основной модуль**: `ai-agent.module.ts`
- **Shared компоненты**: общие сервисы и утилиты
- **Endpoints**: отдельные папки для каждой функциональности
- **Types**: типы и интерфейсы

---

## 📁 Структура файлов

### 🔧 Основные компоненты

#### `ai-agent.module.ts`

**Назначение**: Главный модуль AI Agent, объединяющий все функциональные модули

**Ключевые особенности**:

- Импортирует все endpoint модули
- Настраивает ScheduleModule для cron jobs
- Экспортирует модули для использования в других частях приложения

**Импорты**:

```typescript
-AnalyzeNewTasksModule -
  CheckProgressTasksModule -
  CheckEntityExistsModule -
  ExecuteTasksModule -
  RunAutoWorkflowModule -
  AnalyzeHaircutTasksModule -
  ExecuteHaircutTasksModule -
  AutoHaircutMonitorModule -
  SharedModule;
```

#### `shared/shared.module.ts`

**Назначение**: Модуль для общих сервисов AI Agent

**Экспорты**:

- `AiAgentSchedulerService` - сервис для планирования автоматических задач

#### `shared/ai-agent-scheduler.service.ts`

**Назначение**: Планировщик автоматических задач с использованием cron jobs

**Основные функции**:

1. **`handleAutoWorkflow()`** (ОТКЛЮЧЕН)
   - Запускал AI workflow каждую минуту
   - Теперь заменен на webhook для мгновенной реакции
   - Оставлен как fallback

2. **`handleHaircutScheduler()`** (ОТКЛЮЧЕН)
   - Анализировал задачи о стрижках каждую минуту
   - Выполнял двухэтапный процесс:
     - Анализ задач в New (перемещение в In Progress или Questions)
     - Выполнение стрижек в In Progress (перемещение в Review)

3. **`handleFallbackAnalysis()`** (АКТИВЕН)
   - Запускается каждый час (`@Cron('0 */1 * * *')`)
   - Анализирует задачи, которые могли быть пропущены webhook'ом
   - Служит как система резервного копирования

**Логирование**: Подробные логи с эмодзи для легкой идентификации операций:

- ⏰ - плановые операции
- ✂️ - операции со стрижками
- 🔍 - fallback анализ

#### `shared/ai-base.service.ts`

**Назначение**: Базовый сервис с общей логикой для всех AI операций

**Основные методы**:

- `analyzeNewTask()` - анализ новых задач
- `analyzeEntityCreationTask()` - анализ задач создания сущностей
- `analyzeHaircutTask()` - анализ задач о стрижках
- `isHaircutRelated()` - определение задач о стрижках/красоте
- `executeTaskDecision()` - выполнение решений по задачам

**Dependencies**:

- `GetColumnTasksService` - получение задач из колонок
- `MoveTaskService` - перемещение задач
- `AddTaskCommentService` - добавление комментариев
- `CheckEntityExistsService` - проверка существования сущностей

#### `types/ai-agent.interface.ts`

**Назначение**: Типы и интерфейсы для AI Agent

**Основные интерфейсы**:

1. **`TaskAnalysisResult`**

```typescript
{
  taskKey: string;
  isUnderstandable: boolean;
  decision: 'move_to_progress' | 'move_to_questions' | 'stay_in_new';
  reason: string;
  suggestedComment?: string;
}
```

2. **`TaskProgressResult`**

```typescript
{
  taskKey: string;
  isCompleted: boolean;
  decision: 'move_to_review' | 'stay_in_progress';
  reason: string;
  suggestedComment?: string;
}
```

3. **`WorkflowExecutionResult`**

```typescript
{
  newTasksProcessed: TaskAnalysisResult[];
  progressTasksProcessed: TaskProgressResult[];
  totalTasksMoved: number;
  errors: string[];
  timestamp: string;
}
```

## 🎯 Endpoints (Функциональные модули)

### 1. `analyze-new-tasks/`

**Назначение**: Анализ задач в колонке "New"

#### Файлы:

- **Controller**: `POST /ai-agent/analyze-new-tasks`
- **Service**: Логика анализа новых задач
- **DTO**: Структуры данных для запросов/ответов
- **Interface**: Интерфейсы специфичные для этого endpoint
- **Module**: Модуль endpoint'а
- **Spec**: Тесты

#### Функциональность:

- Получает все задачи из колонки "New"
- Анализирует каждую задачу с помощью `AiBaseService`
- Перемещает понятные задачи в "In Progress"
- Непонятные задачи перемещает в "Questions"
- Возвращает подробный отчет об анализе

### 2. `check-progress-tasks/`

**Назначение**: Проверка задач в состоянии "In Progress"

#### Функциональность:

- Анализирует задачи в колонке "In Progress"
- Определяет, готовы ли задачи к переходу в "Review"
- Автоматически перемещает завершенные задачи

### 3. `check-entity-exists/`

**Назначение**: Проверка существования сущностей

#### Функциональность:

- Проверяет, существуют ли уже запрашиваемые сущности
- Предотвращает дублирование работы
- Возвращает информацию о статусе сущности

### 4. `execute-tasks/`

**Назначение**: Выполнение задач (общий endpoint)

#### Функциональность:

- Универсальное выполнение различных типов задач
- Обработка результатов выполнения
- Логирование процесса выполнения

### 5. `run-auto-workflow/`

**Назначение**: Запуск автоматического workflow

#### Функциональность:

- Комплексный анализ всех колонок
- Координация между различными типами задач
- Общий отчет о выполнении workflow

### 6. `analyze-haircut-tasks/`

**Назначение**: Специализированный анализ задач о стрижках

#### Функциональность:

- Распознавание задач, связанных с стрижками/красотой
- Специальная логика обработки beauty-related задач
- Интеграция с системой выполнения стрижек

### 7. `execute-haircut-tasks/`

**Назначение**: Выполнение задач о стрижках

#### Функциональность:

- Автоматическое "выполнение" стрижек
- Добавление результатов и фотографий
- Перемещение в колонку "Review"

### 8. `auto-haircut-monitor/`

**Назначение**: Мониторинг автоматических стрижек

#### Функциональность:

- Отслеживание состояния автоматических процессов стрижек
- Контроль качества выполнения
- Предоставление статистики

## 🔄 Рабочий процесс (Workflow)

### Основной поток задач:

```
New → [AI Analysis] → In Progress/Questions
In Progress → [Progress Check] → Review/Stay
```

### Специальный поток для стрижек:

```
New → [Haircut Analysis] → In Progress/Questions
In Progress → [Haircut Execution] → Review
```

### Система мониторинга:

- **Webhook-driven**: мгновенная реакция на изменения
- **Cron fallback**: почасовая проверка пропущенных задач
- **Logging**: подробные логи всех операций

## 🚀 Использование

Модуль может работать в двух режимах:

1. **Автоматический** - через webhook'и и cron jobs
2. **Ручной** - через REST API вызовы к specific endpoints

Все endpoints доступны через Swagger UI и могут быть вызваны независимо для тестирования или ручного управления.
