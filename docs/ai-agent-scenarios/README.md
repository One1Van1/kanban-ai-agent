# 📋 AI Agent - Общие сценарии workflow

## 🎯 Описание

Документация всех автоматизированных сценариев обработки задач в AI Agent системе.

## 📂 Доступные сценарии

### 💇 [Сценарий стрижки](./haircut-workflow.md)

**Статус**: ✅ Полностью реализован и автоматизирован

Полный workflow обработки задач стрижек:

- New → In Progress/Questions (анализ)
- In Progress → Review (выполнение)
- Автоматический мониторинг каждую минуту

**Модули**: `analyze-new-haircut-tasks/`, `check-haircut-progress/`, `execute-haircut-tasks/`, `auto-haircut-monitor/`

---

### 🔧 Общие задачи (не стрижки)

**Статус**: ⚠️ Частично реализован (базовая логика)

Обработка общих задач разработки, поддержки, etc:

- New → In Progress/Questions (базовый анализ)
- In Progress → Review (базовая проверка)

**Модули**: `analyze-new-tasks/`, `check-progress-tasks/`, `execute-tasks/`

---

### 🏗️ Создание сущностей

**Статус**: ❌ Отключен (закомментирован в коде)

Логика создания бизнес-сущностей в системе.

**Модули**: `check-entity-exists/` (базовый функционал)

---

## 🚀 Архитектура модулей

### Принцип "Один блок = Одна задача"

```
src/ai-agent/
├── [scenario-name]/          # Конкретный сценарий
│   ├── controller.ts         # API эндпоинты
│   ├── service.ts           # Бизнес-логика
│   ├── dto.ts               # Входящие данные
│   ├── interface.ts         # Типы ответов
│   ├── module.ts            # NestJS модуль
│   └── spec.ts              # Тесты
```

### Принцип "Один эндпоинт = Одна папка"

Каждый REST эндпоинт имеет собственную папку со всем необходимым кодом.

## 🔄 Общий workflow pattern

```
📋 Input Column → 🤖 [AI Analysis] → 🔧 Processing Column → 🤖 [AI Execution] → ✅ Output Column
                                ↓
                         ❓ Questions (если нужны уточнения)
```

## ⚙️ Автоматизация

### Глобальный планировщик

- **Каждую минуту**: основной цикл обработки активных сценариев
- **Каждый час**: fallback анализ для пропущенных задач

### Webhook интеграция

- Jira webhook'и для мгновенного реагирования на изменения
- Автоматический запуск соответствующих сценариев

## 🛠️ Разработка новых сценариев

### Шаги для добавления нового сценария:

1. **Создать структуру папок** согласно архитектуре
2. **Определить workflow** (колонки и переходы)
3. **Реализовать анализ** (распознавание типа задач)
4. **Добавить в планировщик** (автоматическое выполнение)
5. **Настроить мониторинг** (логи и метрики)

### Пример минимального сценария:

```typescript
// analyze-[scenario]-tasks/
export class AnalyzeScenarioTasksService {
  async analyzeScenarioTasks() {
    // 1. Получить задачи из колонки
    // 2. Определить относится ли к сценарию
    // 3. Принять решение куда переместить
    // 4. Выполнить перемещение + комментарий
  }
}
```

## 📊 Мониторинг и отчетность

### Стандартные метрики для каждого сценария:

- `tasksAnalyzed` - проанализировано задач
- `tasksMoved` - перемещено задач
- `tasksCompleted` - завершено задач
- `errors` - количество ошибок

### Логирование:

- Детальные логи каждого этапа
- Статистика выполнения
- Ошибки с контекстом

## 🔧 API Management

### Swagger документация

Доступна по адресу: `http://localhost:3000/api`

### Стандартные эндпоинты для каждого сценария:

- `POST /ai-agent/[scenario-name]` - ручной запуск
- `GET /ai-agent/[scenario-name]/status` - статус выполнения
- `POST /ai-agent/[scenario-name]/settings` - настройки (где применимо)

## 🎯 Цели системы

1. **Полная автоматизация** рутинных процессов
2. **Интеллектуальная обработка** различных типов задач
3. **Масштабируемость** для новых сценариев
4. **Надежность** с fallback механизмами
5. **Мониторинг** всех процессов в реальном времени
