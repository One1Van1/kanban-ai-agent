# 📦 Features (Блоки функциональности)

## 🎯 Что такое Features?

**Features** (блоки) — это изолированные модули приложения, каждый из которых отвечает за **одну конкретную задачу**.

Это аналог модулей на бэкенде, следующий принципу **"ONE BLOCK = ONE TASK"**.

---

## 🗂️ Структура Features

```
features/
├── agents/              # Управление AI агентами
├── flows/               # Управление флоу (потоками)
├── flow-builder/        # Конструктор флоу (drag-and-drop)
├── kanban/              # Канбан доска
└── analytics/           # Аналитика (будущее)
```

---

## 📋 Список блоков

### 1. 🤖 Agents (Агенты)

**Назначение:** Создание, настройка и управление AI агентами.

**Основные функции:**

- Список всех агентов
- Создание нового агента
- Настройка агента
- Выполнение действий агента

**Файлы:** `features/agents/`

---

### 2. 🔄 Flows (Управление флоу)

**Назначение:** Просмотр, редактирование и управление существующими флоу.

**Основные функции:**

- Список всех флоу
- Просмотр деталей флоу
- Редактирование метаданных флоу
- Клонирование флоу
- Экспорт/импорт флоу
- Деплой флоу в агента

**Файлы:** `features/flows/`

---

### 3. 🎨 Flow Builder (Конструктор флоу)

**Назначение:** Визуальный конструктор для создания флоу через drag-and-drop.

**Основные компоненты:**

- **Canvas** — холст для создания флоу
- **Blocks** — блоки (Action, Logic, Wait, Context, Trigger)
- **Toolbar** — панель инструментов
- **Sidebar** — палитра блоков
- **Properties** — панель свойств блока
- **Dialogs** — диалоги (сохранение, удаление и т.д.)
- **Edges** — связи между блоками

**Файлы:** `features/flow-builder/`

---

### 4. 📋 Kanban (Канбан доска)

**Назначение:** Управление задачами на канбан доске.

**Основные функции:**

- Просмотр задач
- Создание задач
- Перемещение задач между колонками
- Редактирование задач
- Комментарии к задачам

**Файлы:** `features/kanban/`

---

### 5. 📊 Analytics (Аналитика) - Будущее

**Назначение:** Аналитика производительности и статистика.

**Файлы:** `features/analytics/` (пока не реализовано)

## 🏗️ Структура каждого блока

Каждый блок имеет **единую структуру**:

```
features/[feature-name]/
├── README.md              # Описание блока
├── components/            # Компоненты блока
├── hooks/                 # Хуки для логики
├── stores/                # Zustand store (состояние)
├── api/                   # API методы блока
├── types/                 # TypeScript типы
└── utils/                 # Вспомогательные функции
```

---

## 🔧 Как создать новый блок?

1. Скопируйте шаблон `FEATURE_README_TEMPLATE.md`
2. Создайте папку `features/[new-feature]/`
3. Создайте структуру папок (components, hooks, stores, api, types, utils)
4. Заполните README.md
5. Создайте API клиент в `api/[new-feature].api.ts`
6. Создайте store в `stores/[new-feature].store.ts`
7. Добавьте описание блока в этот файл

---

## 📝 Правила работы с блоками

1. **Изоляция:** Каждый блок независим и не должен напрямую импортировать из других блоков
2. **Shared:** Общие компоненты, хуки, утилиты — только из `shared/`
3. **Entities:** Модели данных — из `entities/`
4. **API:** Каждый блок имеет свой API клиент
5. **Naming:** Все файлы в kebab-case, компоненты в PascalCase

## 🚀 Импорты

**Используйте path aliases:**

```typescript
// ✅ Правильно
import { Button } from '@/shared/components/ui/button';
import { useAgents } from '@/features/agents/hooks/use-agents';
import { Agent } from '@/entities/agent/agent.entity';

// ❌ Неправильно
import { Button } from '../../../shared/components/ui/button';
```
