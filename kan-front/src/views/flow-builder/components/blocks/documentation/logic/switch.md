# Switch

## Что это

Множественный выбор - выбрать один из нескольких вариантов в зависимости от значения.

## Зачем нужен

- Обработка разных типов событий
- Маршрутизация по статусу
- Разные действия для разных значений
- Альтернатива множественным Condition

## Поля

### Switch Value

Значение для проверки

Обычно переменная: `{task.status}`, `{user.role}`, `{event.type}`

### Cases

Варианты (ветки)

Каждый вариант:

- **Value** - значение для сравнения
- **Blocks** - блоки для выполнения

### Default Case (опционально)

Что выполнить если ни один вариант не подошёл

Как `else` в условии

## Примеры использования

### Обработка статуса задачи

```
Switch: {task.status}

Case "todo":
  → Назначить ответственного
  → Отправить уведомление

Case "in_progress":
  → Проверить дедлайн
  → Если просрочена - эскалация

Case "done":
  → Обновить статистику
  → Отправить на ревью

Case "blocked":
  → Уведомить руководителя
  → Создать задачу на разблокировку

Default:
  → Залогировать неизвестный статус
```

### Роутинг по типу события

```
Switch: {event.type}

Case "task.created":
  → Назначить ответственного
  → Создать подзадачи если нужно

Case "task.updated":
  → Синхронизировать с Jira

Case "task.deleted":
  → Архивировать данные
  → Уведомить связанных пользователей

Case "task.commented":
  → Уведомить упомянутых пользователей

Default:
  → Игнорировать
```

### Обработка по приоритету

```
Switch: {task.priority}

Case "critical":
  → Немедленно назначить старшему
  → SMS уведомление
  → Эскалация руководителю

Case "high":
  → Назначить опытному специалисту
  → Email уведомление

Case "medium":
  → Добавить в очередь
  → Стандартное уведомление

Case "low":
  → Автоматически назначить через балансировщик

Default:
  → Установить priority = "medium"
```

### Обработка платежей

```
Switch: {payment.status}

Case "pending":
  → Отправить напоминание об оплате
  → Если > 3 дней - отменить заказ

Case "processing":
  → Ждать подтверждения от банка

Case "completed":
  → Обновить заказ → "paid"
  → Отправить чек
  → Запустить выполнение заказа

Case "failed":
  → Уведомить клиента
  → Предложить другой способ оплаты

Case "refunded":
  → Обновить заказ → "refunded"
  → Уведомить склад

Default:
  → Залогировать неизвестный статус
```

### Тип пользователя

```
Switch: {user.type}

Case "admin":
  → Полный доступ
  → Логировать все действия

Case "manager":
  → Доступ к своей команде
  → Права на создание задач

Case "developer":
  → Доступ к задачам
  → Права на обновление

Case "guest":
  → Только просмотр
  → Без изменений

Default:
  → Отказать в доступе
```
