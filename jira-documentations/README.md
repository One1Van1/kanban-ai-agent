# Jira Integration API Documentation

## Обзор

Модуль интеграции с Jira предоставляет полнофункциональный API для взаимодействия с системой управления задачами Jira. Все эндпойнты разработаны по принципу "один эндпойнт = одна папка" и следуют архитектуре проекта.

## Базовый URL

```
http://localhost:3000/jira
```

## Аутентификация

Все эндпойнты используют конфигурацию Jira API из переменных окружения:

- `JIRA_HOST` - URL Jira сервера
- `JIRA_USERNAME` - Имя пользователя
- `JIRA_API_TOKEN` - API токен
- `JIRA_PROJECT_KEY` - Ключ проекта по умолчанию

## Общие принципы работы

### Обработка ошибок

Все эндпойнты используют стандартную обработку ошибок:

```json
{
  "statusCode": 400,
  "message": "Описание ошибки",
  "error": "Bad Request",
  "timestamp": "2025-09-23T15:04:11.000Z",
  "path": "/jira/tasks/INVALID-KEY"
}
```

### Коды ответов

- **200 OK** - Успешное выполнение
- **400 Bad Request** - Ошибка валидации данных
- **401 Unauthorized** - Ошибка аутентификации
- **403 Forbidden** - Недостаточно прав
- **404 Not Found** - Ресурс не найден
- **500 Internal Server Error** - Внутренняя ошибка сервера

### Валидация данных

Все входящие данные валидируются через DTO с использованием `class-validator`:

- Обязательные поля проверяются на наличие
- Типы данных валидируются
- Ограничения значений применяются
- Пользовательские валидаторы для специфичных случаев

## Общие типы данных

### Task Interface

```typescript
interface JiraTask {
  key: string;
  fields: {
    summary: string;
    description?: string;
    status: {
      name: string;
      id: string;
    };
    assignee?: {
      displayName: string;
      emailAddress: string;
    };
    priority: {
      name: string;
      id: string;
    };
    created: string;
    updated: string;
  };
}
```

### Status/Column Names

Доступные статусы в системе:

- **New** - Новые задачи
- **backlog** - Бэклог
- **Questions** - Вопросы
- **In Progress** - В работе
- **Review** - На проверке
- **Done** - Завершено

### Priority Levels

- **Highest** - Критический
- **High** - Высокий
- **Medium** - Средний
- **Low** - Низкий
- **Lowest** - Минимальный

## Конфигурация

### Переменные окружения

```bash
# Jira Configuration
JIRA_HOST=https://your-domain.atlassian.net
JIRA_USERNAME=your-email@example.com
JIRA_API_TOKEN=your-api-token
JIRA_PROJECT_KEY=KAN

# Optional
JIRA_BOARD_ID=1
JIRA_MAX_RESULTS=50
```

### Получение API Token

1. Перейдите в [Atlassian Account Settings](https://id.atlassian.com/manage-profile/security/api-tokens)
2. Нажмите "Create API token"
3. Введите название токена
4. Скопируйте созданный токен

## Производительность

### Кэширование

- Результаты переходов кэшируются на 5 минут
- Информация о статусах кэшируется на 10 минут
- Метаданные проекта кэшируются на 1 час

### Ограничения

- Максимум 100 запросов в минуту на IP
- Максимум 1000 результатов поиска за раз
- Максимальный размер файла: 10 MB

### Оптимизация

- Используйте поиск с ограничением `maxResults`
- Кэшируйте часто запрашиваемые данные
- Избегайте сложных JQL запросов без необходимости

## Мониторинг и логирование

### Логирование

Все операции логируются с уровнями:

- **INFO** - Успешные операции
- **WARN** - Предупреждения
- **ERROR** - Ошибки операций
- **DEBUG** - Отладочная информация

### Метрики

Отслеживаются:

- Время ответа эндпойнтов
- Количество ошибок
- Частота использования
- Размер передаваемых данных

## Безопасность

### Защита данных

- Все API токены шифруются
- Логирование не содержит чувствительных данных
- Валидация входящих данных на XSS и injection

### Права доступа

- Операции выполняются от имени настроенного пользователя
- Доступ к задачам ограничен правами в Jira
- Файлы проходят проверку на безопасность

3. **Timeout** - Проверьте доступность Jira сервера
